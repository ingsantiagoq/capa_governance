# Inteligencia de mercado para Domain Experts

El conocimiento de SAP, Microsoft Dynamics, Epicor, Oracle y Odoo funciona como presión de diseño. No prueba que UBP ya implemente una capacidad ni autoriza copiar arquitectura o comportamiento.

Cada lección publicada debe registrar fuente oficial, fecha de verificación, capacidad observada, problema que resuelve, aprendizaje y decisión explícita para UBP. Las fuentes secundarias pueden orientar una búsqueda, pero no sostienen un gate.

El experto revisa sus fuentes dentro del periodo declarado en `refreshDays` y antes si cambia una versión mayor del producto observado. Una referencia vencida no invalida hechos históricos, pero bloquea usarla como fundamento de una decisión nueva hasta revalidarla.

La comparación debe responder tres preguntas:

1. ¿Qué problema recurrente ya resolvió el mercado?
2. ¿Qué costo, límite o error revela esa solución?
3. ¿Qué adopta, adapta o evita UBP para mejorar su propia North Star?

El gate mantiene separadas evidencia UBP y evidencia de mercado. Solo el código, contratos, ADR/CAPA vigente y pruebas de UBP pueden elevar madurez de implementación.
